# Database Reference

SQL Server (MSSQL) — schema applied by running `scripts/mssql/` in order (01 → 15).
Script 15 is the final state; earlier scripts show the migration history.
All timestamps are UTC (`SYSUTCDATETIME()`). Soft-delete is the pattern everywhere — no hard deletes except via the admin purge procedure.

---

## Tables

### `dbo.files`

One row per uploaded file. The authoritative record of what is in the knowledge base.

| Column | Type | Why it exists |
|--------|------|---------------|
| `id` | `INT IDENTITY` PK | Stable integer handle used everywhere in the app and in queue messages. |
| `name` | `NVARCHAR(255)` NOT NULL | Original file name as uploaded. The chat pipeline uses this as the human-readable citation label — it is the only citable name the model ever sees. |
| `mimetype` | `NVARCHAR(100)` NOT NULL | MIME type declared at upload time (e.g. `application/pdf`). Used in download responses (`Content-Type`) and stored for reference. |
| `file_path` | `NVARCHAR(1000)` NOT NULL | Where the original file lives in the file store. An absolute `https://` URL under Azure Blob, or a store-relative path under a mounted volume. Both forms are handled by `app/logic/files.extract_blob_path_from_url`. |
| `extracted_text_path` | `NVARCHAR(1000)` NULL | Path to the plain-text (or Docling JSON) file that the parsing service wrote after ingestion. `NULL` until `kb_worker` finishes parsing. Fed to the indexer and to the catalog describer. |
| `vector_store_file_id` | `NVARCHAR(255)` NULL | The `source_file_id` UUID that the indexer minted for this file's chunks in the vector store (MongoDB or Qdrant). `NULL` until indexing completes. Used to move or deactivate chunks when a file is disabled or deleted. |
| `processing_status` | `NVARCHAR(20)` NOT NULL DEFAULT `'pending'` | Four states: `pending` → `processing` → `completed` or `failed`. Written by `kb_worker` via `update_file_processing_status`. Lets the upload API return immediately while the browser polls `GET /files/{id}/status`. |
| `processing_error` | `NVARCHAR(1000)` NULL | The failure reason when `processing_status = 'failed'`. Set by `handle_dead_letter` after the worker exhausts retries. |
| `is_active` | `BIT` NOT NULL DEFAULT `1` | Soft-delete flag. `DELETE /files/{id}` sets this to 0; it does not remove the row. Also set to 0 by `PATCH /files/{id}/status` for DISABLE/INACTIVE. A `0` row's chunks are moved out of the active vector-store collection so they stop being searchable. |
| `content_hash` | `NVARCHAR(64)` NULL | SHA-256 hex of the uploaded bytes. Used by the duplicate-upload check (`find_file_by_content_hash`) so an identical file is refused with a 409 unless `allow_duplicate=true` is passed. Indexed (`ix_files_content_hash`). |
| `document_key` | `NVARCHAR(255)` NULL | The document this file is a version of: the file name lower-cased, stripped of extension and trailing `_v<n>` tag (e.g. `policy_manual`). All uploads with the same key form a version group. `NULL` for files uploaded before versioning was introduced. Indexed with `version_number` (`ix_files_document_key`). |
| `version_number` | `INT` NOT NULL DEFAULT `1` | Which upload of this document this is (1, 2, 3…). Never reused after a delete — `next_document_version` counts inactive rows too. |
| `is_latest` | `BIT` NOT NULL DEFAULT `1` | Whether this is the newest ingested version. `promote_latest_version` elects the highest `version_number` among active, indexed rows and sets all others to 0. The vector store mirrors this flag onto each chunk so searches stay on the latest by default. |
| `version_label` | `NVARCHAR(50)` NULL | A human-readable version name parsed from the file name or passed as a query parameter at upload time (e.g. `3.2`). Optional. |
| `effective_date` | `DATE` NULL | When this version took effect, supplied by the uploader. Stored in SQL but **not yet copied into the vector-store chunk metadata**, so it cannot currently be used for date-range queries at retrieval time. |
| `created_by` | `NVARCHAR(255)` NOT NULL | Email of the admin who uploaded the file. |
| `created_on` | `DATETIME2` NOT NULL | Upload timestamp. |
| `updated_by` | `NVARCHAR(255)` NULL | Last writer (kb_worker for status updates, admin for deletes). |
| `updated_on` | `DATETIME2` NULL | Timestamp of the last change. |

### `dbo.chatbot_session`

One row per conversation thread. A session is a named container for a sequence of chat turns.

| Column | Type | Why it exists |
|--------|------|---------------|
| `id` | `NVARCHAR(36)` GUID PK | UUID generated by `NEWID()`. Returned to the browser as the conversation handle. |
| `name` | `NVARCHAR(255)` NOT NULL | User-given or auto-generated conversation title shown in the sidebar. |
| `entity_id` | `NVARCHAR(36)` NOT NULL | External entity identifier (carries a default placeholder UUID). Reserved for multi-tenancy — not actively filtered on yet. |
| `tenant_id` | `NVARCHAR(36)` NOT NULL | External tenant identifier (same status as `entity_id`). |
| `user_id` | `NVARCHAR(36)` NOT NULL | External user identifier from the calling system (separate from `created_by`). Placeholder default is set when creating sessions under the legacy auth path. |
| `user_type` | `NVARCHAR(50)` NOT NULL DEFAULT `'demo_user'` | Caller's role in the external system (e.g. `demo_user`, `employee`). Not currently used for access control within this service. |
| `is_admin` | `BIT` NOT NULL DEFAULT `0` | Whether the external caller had admin rights when the session was created. |
| `is_active` | `BIT` NOT NULL DEFAULT `1` | Soft-delete flag. `DELETE /chat/sessions/{id}` sets this to 0. |
| `created_by` | `NVARCHAR(255)` NOT NULL | Email of the user who opened the session. |
| `created_on` | `DATETIME2` NOT NULL | When the session was created. |
| `updated_by` / `updated_on` | `NVARCHAR(255)` / `DATETIME2` NULL | Last modification. |

### `dbo.chatbot_history`

One row per chat turn (one user question + one assistant answer). The session's message log.

| Column | Type | Why it exists |
|--------|------|---------------|
| `id` | `NVARCHAR(36)` GUID PK | UUID for this turn. Passed to the trace, feedback, and grounding tables as their foreign key. |
| `conversation_id` | `NVARCHAR(36)` NOT NULL | The `chatbot_session.id` this turn belongs to. Indexed with `created_on` for efficient session history fetches (`ix_chatbot_history_session`). |
| `prompt` | `NVARCHAR(MAX)` NOT NULL | The user's raw question. Also used by `user_context.recent_questions_of` to surface recent questions back into the prompt for context. |
| `response` | `NVARCHAR(MAX)` NULL | The assistant's full answer. Written by a second `upsert_chatbot_history` call after streaming completes; `NULL` while the turn is in flight. |
| `error` | `NVARCHAR(MAX)` NULL | If the turn failed, the error message. A non-NULL value here is what `chat_metrics` counts as `errors`. |
| `is_active` | `BIT` NOT NULL DEFAULT `1` | Soft-delete flag. |
| `rag_collections` | `NVARCHAR(MAX)` NULL | JSON array of the vector-store collections that were searched for this turn. Stored for debugging — tells you which index a retrieval hit came from. |
| `grounding_verdict` | `NVARCHAR(20)` NULL | Post-hoc citation check result: `grounded`, `partial`, or `unsupported`. Written by the background grounding task (`chat_grounding.py`) after the answer has already been sent. `NULL` if the check is disabled or hasn't run yet. |
| `grounding_detail` | `NVARCHAR(MAX)` NULL | The grounding checker's per-citation breakdown (JSON). |
| `grounding_checked_on` | `DATETIME2` NULL | When the grounding check ran. |
| `created_by` | `NVARCHAR(255)` NOT NULL | Email of the user who sent the message. |
| `created_on` | `DATETIME2` NOT NULL | When the turn started. |
| `updated_by` / `updated_on` | NULL | Last modification (grounding write, error update). |

---

### `dbo.chatbot_feedback`

Thumbs up / thumbs down on a specific chat turn, with an optional comment.

| Column | Type | Why it exists |
|--------|------|---------------|
| `id` | `NVARCHAR(36)` GUID PK | Unique ID for this feedback record. |
| `history_id` | `NVARCHAR(36)` NOT NULL | The `chatbot_history.id` being rated. No FK constraint — ownership is enforced in `app/routers/chat.py` (a caller can only rate their own turns). Indexed (`ix_chatbot_feedback_history`). |
| `rating` | `NVARCHAR(20)` NOT NULL | `'positive'` or `'negative'`. CHECK constraint enforced. On an update the full state is replaced (no COALESCE), so switching from thumbs-down to thumbs-up always clears the comment. |
| `comment` | `NVARCHAR(MAX)` NULL | Optional free-text comment, typically on a negative rating. |
| `created_by` | `NVARCHAR(255)` NOT NULL | Email of the rater. |
| `created_on` | `DATETIME2` NOT NULL | When the feedback was submitted. |
| `updated_by` / `updated_on` | NULL | If the user changed their rating. |

### `dbo.audit_log`

Two purposes in one table, distinguished by `action`:

**Admin audit trail** — who did what to which file or user account:

| Column | Type | Why it exists |
|--------|------|---------------|
| `id` | `NVARCHAR(36)` GUID PK | Unique row ID. |
| `created_on` | `DATETIME2` NOT NULL | When the action happened. Indexed DESC (`ix_audit_log_created_on`). |
| `actor` | `NVARCHAR(255)` NOT NULL | Email of the person who triggered the action. |
| `action` | `NVARCHAR(50)` NOT NULL | What happened: `file_upload`, `file_delete`, `file_duplicate`, `login`, `password_change`, etc. `chat_trace` is reserved for the trace rows below. |
| `target` | `NVARCHAR(500)` NULL | What was acted on (e.g. `"42:policy_manual.pdf"`, `"alice@example.com"`). |
| `result` | `NVARCHAR(20)` NOT NULL DEFAULT `'ok'` | `'ok'` or `'refused'` (e.g. a duplicate upload that was blocked). |
| `detail` | `NVARCHAR(MAX)` NULL | JSON with extra context (file bytes, SHA-256, version number, etc.). CHECK constraint enforces valid JSON. |

**Chat turn trace** — one row per answered turn (written by the system, not a user):

| Column | Type | Why it exists |
|--------|------|---------------|
| `history_id` | `NVARCHAR(36)` NULL | The `chatbot_history.id` this trace is for. Indexed (`ix_audit_log_history_id`). When `action = 'chat_trace'` this is the join key; for non-trace rows it is NULL. |
| `chat_outcome` | `NVARCHAR(40)` NULL | How the turn was classified: `answered`, `no_evidence`, `chitchat`, `kb_overview`. Populated only on `chat_trace` rows. Used by `chat_metrics`. |
| `model` | `NVARCHAR(100)` NULL | The LLM model ID used for this turn (e.g. `gpt-4o`). |
| `config_version` | `NVARCHAR(40)` NULL | The prompt/config version string at the time of the turn. Lets you correlate quality changes to config deploys. |
| `total_ms` | `INT` NULL | End-to-end wall-clock time for the turn in milliseconds. Used by `chat_metrics` for `avg_total_ms` and `p95_total_ms`. |
| `top_retrieval_score` | `FLOAT` NULL | The similarity score of the highest-ranked chunk retrieved. Low values indicate the question was far from anything in the knowledge base. |
| `detail` | `NVARCHAR(MAX)` NULL | Full JSON trace of the turn: steps executed, intent, retrieved chunks, citations, timing breakdown. Written by `app/logic/trace.py`. |

> `filter_audit_log` excludes `action = 'chat_trace'` rows — they are read via `get_chatbot_trace` instead.
> `purge_audit_and_trace` can age the two kinds out on independent retention schedules.

## Relationships

```
dbo.files
  └── (vector_store_file_id ties to MongoDB/Qdrant chunks — no SQL FK)

dbo.chatbot_session
  └── dbo.chatbot_history  (conversation_id → session.id, no FK constraint)
        ├── dbo.chatbot_feedback  (history_id → history.id, no FK constraint)
        └── dbo.audit_log         (history_id, action='chat_trace')
```

No SQL foreign key constraints anywhere — ownership is enforced in application code. This was a deliberate choice: it lets `dbo.users` be dropped (script 14) without cascading failures, and it keeps the schema additive-only across migrations.

## Conventions

- **Soft delete everywhere.** `is_active = 0` hides a row; it is never physically removed except by the `purge_audit_and_trace` procedure.
- **GUID PKs on chat tables, INT on files.** The chat tables switched to GUIDs in script 14 to allow distributed ID generation. `dbo.files` kept `INT IDENTITY` because file IDs appear in queue messages and the indexer, and changing them would require coordinating two services.
- **No FK constraints.** Ownership is checked in `app/routers/` code (e.g. a user can only rate their own turns). The tradeoff: a referential integrity bug will not be caught by the database.
- **NULL = unchanged.** Every `upsert_*` procedure uses `COALESCE(@new, existing)` on updates, so callers can send a partial update without overwriting fields they did not touch. Exception: `upsert_chatbot_feedback` always replaces `rating` and `comment` outright, because feedback is always submitted as a complete state.
- **`created_by` vs `owner_id`.** `created_by` is the caller's email string (always set). `owner_id` was an INT FK to `dbo.users`; it was dropped in script 15 after `dbo.users` was removed. Session and history ownership is now tracked only through `created_by`.
